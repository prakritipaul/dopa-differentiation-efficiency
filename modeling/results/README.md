# `modeling/results/` — what each file is

Every file here is generated. Nothing is hand-edited. If a number in a write-up
disagrees with a file here, the file is right and the write-up is stale.

## Read this first: there are TWO analysis families here

They use different outcomes and different cohorts, and **their numbers are not
comparable**. Telling them apart is the single most important thing about this
directory.

| | **published** | **DA-only untreated** |
|---|---|---|
| filename marker | no `da_untreated` | `_da_untreated` |
| outcome | `(DA + Sert) / all D52 cells` | `DA / all D52 cells` |
| D52 cells counted | **all**, including rotenone-treated | **untreated only** |
| cohort | 138 lines / 159 combos | **136 lines / 157 combos** |
| success threshold | `>= 0.2` → 96 / 42 | `>= 0.2` → **61 / 75** |
| reproduces the paper? | yes, exactly | no — a **deliberate divergence** |

The published family reproduces Jerber et al.'s own definition, which applies a
≥10-cell threshold and never filters on treatment. The DA-only family drops
rotenone-treated cells (a complex-I inhibitor that preferentially damages
dopaminergic neurons — the cells in the numerator) and counts DA alone, because
DA and Sert are separate lineages that do not convert into one another.

Because the outcome is bimodal in one family and unimodal in the other, the
same threshold of 0.2 is doing a different job in each. **A lower number in the
DA-only family is not a regression — it is a harder target.**

## File index

### Model results — the CV grids

| file | generated by |
|---|---|
| `results_{task}.csv` | `run_regression.py` / `run_classification.py` |
| `results_{task}_qualonly.csv` | `run_variant.py --suffix _qualonly` |
| `results_{task}_{D11,D30}_qualonly_da_untreated.csv` | `run_variant.py --timepoint {D11,D30} --suffix _qualonly --label-variant da_untreated` |

`task` is `regression` or `classification`. `_qualonly` means the HVG/PCA basis
was fit only on cells from the qualifying `(cell_line, pool)` combos; without it
the basis also saw cells from lines outside the cohort.

Each table is the **full robustness grid**: 4 CV schemes × {flat, nested} tuning
× 2 models. The DA-only tables are 448 rows each.

### Nested tuning selections

`nested_selections_*.csv` — the per-outer-fold choice made by nested CV, one row
per `(scheme, model, repeat, fold)`. Same naming/suffix scheme as above.

### Feature importance (published family only)

`feature_importance_table_{task}_{model}[_qualonly].csv`, from
`feature_importance.py`.

> ⚠️ **These exist only for the published outcome.** `feature_importance.py`
> raises `NotImplementedError` for any other label variant, on purpose: its
> full-fit columns come from a global PCA basis fit under the *published*
> cohort, so pairing them with fold-level columns from another cohort would
> produce a mixed-basis table. Supporting the DA-only family requires re-running
> `005_d11_pca_features.py` against that cohort first.

### D30 supporting analyses

| file | generated by | what it is |
|---|---|---|
| `d30_celltype_markers.csv` | `d30_celltype_markers.py` | mean log-normalised expression per D30 cell type, for 34 canonical markers. Wide, with a two-row header: row 1 is the marker **panel**, row 2 the **gene**. This is the evidence behind calling FPP/P_FPP progenitors, Epen1 ependymal/choroid-plexus-like, and U_Neur1/2 terminal off-target neurons. |
| `d30_single_feature_benchmarks[_da_untreated].csv` | `d30_single_feature_benchmarks.py` | fit-free reference lines — see below |
| `d30_d52_da_fractions.csv` | ad-hoc | per line: `D30_DA`, `D30_Sert`, `D30_S` (=DA+Sert), `D52_DA`, `D52_DA_Sert`. Backs the finding that D30 DA → D52 DA is ρ +0.93 while D30 Sert → D52 DA is Pearson +0.06. |
| `d52_efficiency_definitions.csv` | ad-hoc | three candidate outcome definitions per line: `dopa_eff_neuron_denom` (DA / all *neurons*), `dopa_share_of_target` (DA / (DA+Sert)), `authors_diff_eff` |
| `d52_untreated_efficiency.csv` | ad-hoc | per line on untreated cells: `da_over_all`, `sert_over_all`, `da_sert_over_all`, `n_cells`. Used as a regression gate when the DA-only label was built. |

## Column reference

### `results_*` — shared

| column | meaning |
|---|---|
| `model` | `ridge`/`lasso` (regression), `logistic_l2`/`logistic_l1` (classification) |
| `k` | number of PCs used, 0–10. For **nested** rows this is the **modal** choice across outer folds, not "the" value |
| `param_str` | the hyperparameter, e.g. `alpha=1.0`, `C=0.1`. Modal for nested rows |
| `scheme` | `plain`, `donor_grouped`, `loco`, `lodo` |
| `tuning` | `flat` (one config scored directly) or `nested` (config re-selected per outer fold on training lines only) |
| `pool_correction` | always `False` — the mechanism was dropped; see `docs/pool_correction_investigation.md` |
| `n_outer_folds` | nested rows only: how many outer folds contributed |
| `selection_distribution` | nested rows only: the **full spread** of selected configs, e.g. `k=3,alpha=1.0 x28; k=2,alpha=1.0 x22` |
| `fold_features` | *(DA-only family)* the fold-features file scored, so a table cannot be silently crossed with another timepoint's |
| `label_variant` | *(DA-only family)* which cohort+label+threshold bundle produced it |

### `results_regression_*`

`mae`, `rmse`, `r2`, and `frac_out_of_range` — the fraction of predictions
falling outside `[0, 1]`, which a linear model on a bounded outcome can produce
and which is worth knowing.

### `results_classification_*`

`roc_auc`, `pr_auc`, `balanced_accuracy`, `sensitivity`, `specificity`, `f1`,
`brier`. Class calls use a 0.5 probability threshold — unrelated to the 0.2
**outcome** threshold that defines success.

### ⚠️ `_mean` / `_std` are ACROSS REPEATS, and `_std` is NaN for `loco`/`lodo`

Every metric is computed **per repeat** — within one repeat the folds together
cover all 136 (or 138) lines exactly once, and that is what makes the number
valid — and only then averaged. `_std` is the standard deviation **across the
10 repeats**, not across folds and not a confidence interval.

`loco` and `lodo` are exhaustive enumerations with exactly **one** repeat
(`repeat=0`), and their out-of-fold predictions are pooled into a single group
before scoring, because a one-line LOCO test fold cannot support ROC-AUC. The
sample SD of one observation is undefined, so **their `_std` cells are
legitimately NaN**. A finite `0.0` there would be worse than useless: it asserts
zero across-repeat variability, a precision claim nobody measured.

### `nested_selections_*`

One row per `(scheme, model, repeat, fold)`: `selected_k`, `selected_param`.
The `results_*` table carries only the modal choice; this is the raw record.

### `d30_single_feature_benchmarks*`

Single columns scored against the outcome with **no model and no fitted
parameter**.

| column | meaning |
|---|---|
| `benchmark` | human-readable name, including which outcome it is matched to |
| `columns` | the `phat_*` columns summed for the numerator |
| `denominator` | if set, the benchmark is a **share** (numerator ÷ these columns) rather than a fraction of all cells |
| `direction` | `+1` or `-1`, **declared a priori in source** |
| `mean_fraction` | mean value across lines |
| `spearman`, `roc_auc` | point estimates |
| `*_lo`, `*_hi` | 95% bootstrap interval |
| `*_n_boot_used` | **how many of the 2,000 resamples were usable** |

Three things here are easy to misread:

**`direction`** — ROC-AUC is direction-sensitive: a feature that perfectly ranks
failures *above* successes scores near 0.0, not 1.0. The expected sign is fixed
in the source *before* looking at results, and AUC is computed on the oriented
score. Flipping a sign after seeing the number would be choosing the
aggregation from the data. `spearman` is reported on the **raw** feature so its
sign still shows which way the biology runs; `roc_auc` is **oriented**.

**`*_n_boot_used`** — the bootstrap resamples **donors** (20 of them) with
replacement, not lines, because 136 of 138 lines share a donor and a line-level
bootstrap would treat correlated lines as independent and give intervals that
are too narrow. A resample can by chance draw only successes, and ROC-AUC is
undefined with one class present. Those resamples yield NaN and are **excluded
from the percentile**, rather than crashing or being silently counted as zero.
This column reports how many of the 2,000 actually contributed, so a
suspiciously narrow interval computed from few resamples is visible rather than
hidden. In practice it reads `2000` throughout; a materially lower number would
mean the interval is not trustworthy.

**These are in-sample reference lines, not model scores.** There is nothing to
cross-validate — with no fitted parameter, a line's prediction is its own
feature value whether or not it was "in training". They bound what a model must
beat. Comparing them to a cross-validated model AUC is not like-for-like.

**Match the numerator to the outcome.** `DA+Sert` is the right "already arrived"
comparator for a DA+Sert outcome; for a DA-only outcome it is `DA` **alone**.
Using the pair against the DA-only outcome understates the ceiling badly — 0.886
versus 0.960 — and that gap is the difference between "the model adds six
points" and "the model does not beat one raw column". Both rows are reported in
`_da_untreated`, each labelled with the outcome it matches.

### `feature_importance_table_*`

`univariate_spearman`, `coefficient`, `regularized_to_zero`,
`selection_frequency`, `loco_delta`, `permutation_delta`, `shap_mean_abs`,
`technical_covariate_eta2`.

`loco_delta` and `permutation_delta` are **paired per-fold** differences
(metric-without minus metric-with, computed within each fold then averaged) —
not two independently averaged CV scores subtracted at the end. The `*_note`
columns flag rows where the comparison is grouped rather than individual:
`phat_P_FPP` is the implicit reference category and was never an explicit
feature to drop, so its row reports the **grouped** delta with both proportions
removed together.

`technical_covariate_eta2` is the fraction of a feature's variance explained by
pool identity. It is high for several PCs — read
`docs/PCA_interpretation.md` before interpreting any PC biologically.

### `pc1_loadings_{D11,D30}_da_untreated.csv`

From `pc1_loadings_analysis.py`. The top 25 HVG loadings at each pole of PC1,
with `gene`, `loading`, `signed_rank` (1..2000) and `pole`.

Only PC1 gets this treatment: PC2/PC3 are near-tied in variance and rotate
between fits, so a gene-level reading of them would not replicate. PC1 does
(r = 0.9995). **The sign is arbitrary** — `pole` labels one end against the
other, and carries no meaning on its own. Interpretation in
`docs/PCA_interpretation.md`; the script also prints the gene-set enrichments
and the composition-vs-state decomposition, which are not saved to CSV.

## Provenance and staleness

- `label_variant` and `fold_features` appear only on the DA-only family.
  Resuming a table whose recorded variant differs from — **or is absent for** —
  the current run raises. Absent means *unknown*, not *compatible*.
- The published tables predate those columns. They are complete and were never
  meant to be resumed.
- `results_{task}.csv` and `results_{task}_qualonly.csv` are the **138-line
  published** results and are deliberately left byte-identical by all later
  work. Every commit touching this directory verifies that by checksum.
- `d30_single_feature_benchmarks.csv` (unsuffixed) is scored against the
  **published** outcome; `_da_untreated` against the new one.

## Regenerating

```bash
# published family
uv run python -m modeling.run_regression
uv run python -m modeling.run_classification

# DA-only untreated family, per timepoint
uv run python -m modeling.run_variant --timepoint D11 --suffix _qualonly \
    --label-variant da_untreated --out-suffix _D11_qualonly
uv run python -m modeling.run_variant --timepoint D30 --suffix _qualonly \
    --label-variant da_untreated --out-suffix _D30_qualonly

# supporting analyses
uv run python -m modeling.d30_single_feature_benchmarks --label-variant da_untreated
uv run python -m modeling.d30_celltype_markers
```

`run_variant` also prints a baseline-vs-variant delta against
`results_{task}.csv`. **For the DA-only family that delta is
apples-to-oranges** — different outcome *and* different cohort — and must not be
read as an improvement or a regression. The valid comparison is D11 vs D30
within the same family, which is paired: both were scored on fold tables
verified to agree on every fold's train/test membership.
